# 架构转产品基线

用于架构边界已经确认，需要建立产品信息架构、端到端用户旅程、PRD 拆分和验收边界时。目标是把架构投影成用户可以理解和操作的产品，而不是让页面重新定义业务事实。

## 转换顺序

1. **识别产品表面与主体**：有哪些应用、入口和用户角色，身份和权限如何隔离或切换。
2. **建立整体信息架构**：每个应用承载哪些一级区域、核心信息、主操作和历史入口。
3. **贯通端到端旅程**：从用户目标和触发事件开始，写清用户输入、平台自动动作、必要决策、结果反馈、退出和恢复。
4. **建立对象投影矩阵**：同一权威对象如何被不同主体读取和操作；页面不得创造第二套状态或版本。
5. **定义跨应用 Handoff**：页面、交易、履约、运营和异常如何传递事实、版本、责任和执行结果。
6. **拆分详细 PRD**：按独立用户结果、产品表面和维护生命周期拆分，不按后台表或 Agent 名称拆分。
7. **建立 UAT 与技术切片映射**：产品承诺、状态、权限、异常和埋点能够对应到实现与验证。

## 用户旅程模板

每条主旅程回答：

- 用户处于什么上下文，想完成什么；
- 用户实际看见和输入什么；
- 平台自动理解、计划、执行和校验什么；
- 哪些步骤必须由用户确认、承担责任或授权外部副作用；
- 成功、失败、等待、修改、放弃和返回时反馈什么；
- 形成哪些事实、版本、Task、Decision、Action 或历史记录；
- 下一步入口在哪里。

自动化默认的流程先定义系统触发事件，不把“用户请求平台检查、分析或修复”作为平台已知条件下的必要前置。

## 建议交付物

- 产品表面与角色关系图；
- 全局导航和页面层级表；
- 关键端到端旅程图；
- 对象可见性与操作矩阵；
- 跨应用 Handoff 表；
- 共享产品规则；
- PRD 拆分边界；
- 待产品确认、待技术实现、待外部验证和不做事项。

## 边界

这一阶段不直接冻结视觉稿、像素、数据库表、Prompt 或供应商参数。旧产品和 Demo 可以作为交互参考，但不能覆盖当前权威架构；复用前应区分可复用交互、直接冲突、表述歧义、实现历史和待核验内容。

完成标准是用户目标能够贯通到业务结果，并且每一步都能解释用户看见什么、平台自动做什么、何时需要人类决策、产生什么权威事实，以及失败后如何恢复。
