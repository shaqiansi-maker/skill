# 记忆与上下文架构

用于系统确实需要跨任务、跨会话、跨阶段或跨作用域保持信息连续性时。目标是让 Agent 减少重复询问并延续有效工作，同时不让历史摘要、模型推断或跨域资料冒充当前权威事实。

## 适用性检查

出现下列任一需求时进入专项设计：

- 长期任务需要中断后恢复，或多个 Task 需要继承前序结论；
- 用户、项目或组织原则需要在后续交互中继续适用；
- 历史 Evidence、知识或生成成果需要按权限复用；
- 上下文过长，需要压缩、分层召回或控制 Token 成本；
- 多 Agent 或 Workflow 需要共享经过控制的信息连续性。

只有日志、聊天记录或数据库，不自动等于需要独立记忆系统。短期、无连续性要求的任务不为形式增加记忆对象、向量检索或长期保存。

## 必须拆开的对象

| 逻辑对象 | 作用 | 不能替代 |
| --- | --- | --- |
| 业务权威对象 | 保存订单、权限、资产版本等正式事实 | 不能由记忆、摘要或向量结果覆盖 |
| 原始来源与历史 | 保存消息、文件、事件及其来源关系 | 不自动成为已确认事实或长期记忆 |
| 运行时上下文 | 当前 Attempt 实际提供给模型的信息 | 不等于长期保存，也不证明信息完整 |
| Context Snapshot | 冻结本次任务实际使用的版本、来源和遗漏范围 | 不取代来源对象本身 |
| Memory Candidate | 从输入或历史中提炼出的待判断内容 | 未经校验不能自动跨任务复用 |
| Durable Memory | 经规则允许、带来源和作用域的长期信息 | 不成为资金、权限或正式状态的权威来源 |
| Curated Knowledge | 经审核后可供一定范围复用的知识 | 不暴露其他主体的原始数据或项目秘密 |
| 正式资产 | 报告、页面、图片、物料等可版本化成果 | 不因被召回就变成记忆或当前有效版本 |

这些是逻辑类别，不预设数据库表，也不是所有产品必须实现的封闭枚举。

## 完整决策域

| 决策维度 | 必须回答的问题 |
| --- | --- |
| 业务目的 | 需要延续什么工作；不记住会造成什么实际阻断 |
| 对象与性质 | 保存的是来源事实、用户陈述、偏好、原则、推断、摘要、知识还是资产引用 |
| 作用域 | 信息属于 Task、项目、用户、组织还是平台；能否以及如何提升作用域 |
| 权威与责任 | 谁提出候选、谁校验、谁确认、谁持久化、谁可以修正或撤销 |
| 写入条件 | 什么事件触发候选；哪些可按 Policy 自动接受，哪些需要人类确认 |
| 检索与注入 | 什么任务可读取；如何检查权限、相关性、新鲜度、冲突和 Token 预算 |
| 生命周期 | 如何版本化、纠正、降级、失效、遗忘、删除、受限保留和恢复 |
| 隐私与安全 | 是否包含敏感信息；用途、同意、跨域使用、审计和最小披露如何控制 |
| 用户可见与控制 | 用户需要看见、纠正、停用或撤回哪些记忆；哪些内部记录不能伪装成用户可编辑事实 |
| 失败与未知 | 提炼错误、召回失败、来源消失、冲突或结果未知时如何降级和人工处理 |
| 可观测与评测 | 如何发现错误提炼、错误召回、陈旧信息、跨域污染和无效上下文注入 |
| 成本与性能 | 数据增长、索引、召回延迟、上下文大小和模型成本如何受控 |
| 演进边界 | V1 最小能力是什么；哪些能力等待真实使用、规模或合规验证 |

这是记忆架构的方法级完整决策域，不表示具体产品必须采用相同对象、字段、状态或存储技术。

## 权威写入与读取主线

```text
原始来源 / 权威对象版本
→ Memory Candidate
→ 确定性检查 + 语义判断 + Policy / 必要人类确认
→ 带来源、作用域、适用条件和版本的 Durable Memory
→ Context Builder 按当前 Task 权限与需要检索
→ 形成可追溯的 Context Snapshot
→ Agent 使用，但不因此获得权威写入权
```

`Context Builder` 表示上下文组装责任，不要求实现为同名服务；本节对象名称同样不预设具体数据库表或部署单元。

- 低风险偏好可以在明确 Policy 下自动形成或更新记忆；真实性责任、授权、商业承诺、敏感信息和跨作用域提升不能仅由 Agent 决定。
- Agent 可以提出记忆候选、冲突或失效建议；正式接受、作用域提升、删除与受限保留由相应 Policy 和确定性 Service 执行。
- 检索结果只说明“本次找到并使用了什么”，不证明没有其他事实，也不自动成为当前有效结论。

## 作用域与隔离

- Task Scope 只服务当前任务；项目结束后是否保留由项目 Policy 决定。
- Project Scope 不因同一用户拥有多个项目而自动跨项目复用。
- User Scope 只保存确实跨项目适用的用户原则或偏好；从项目提升到用户作用域需要明确依据。
- Organization 或 Platform Scope 需要独立权限和发布流程，不能从单个用户或项目静默归纳。
- 跨用户聚合经验必须先去标识、聚合、评审并形成新的 Platform Knowledge；不得让 Agent 直接读取其他用户的原始数据。

无法确定作用域时保留为候选或 `needs_review`，不能默认选择更大的作用域。

## 修正、删除与恢复

- 新事实推翻旧记忆时追加修正和取代关系，不静默改写历史任务使用过的 Snapshot。
- 来源失效或新鲜度不足时，记忆应降级、阻止高风险使用或要求重新核验。
- 用户删除项目、撤回授权或提出隐私请求时，分别判断正常检索删除、法定或交易受限保留、派生记忆失效和跨作用域合法事实；不能只删除界面记录，也不能一律物理清除。
- Compaction、摘要或模型供应商的会话状态只是可替换的 Runtime 能力，不能代替平台持有的 Durable Memory、权威数据和删除记录。
- 记忆服务不可用时，系统应降级为权威数据与必要输入驱动；不能编造连续性，也不能把召回失败写成“用户没有说过”。

## V1 停止线

V1 通常只需：

- 复用现有权威对象、原始来源和正式资产，不另建第二套事实系统；
- 保存少量确有复用价值、带来源和作用域的项目或用户级记忆；
- 由 Context Builder 按任务构建可追溯 Snapshot，并限制检索范围和 Token 预算；
- 支持必要的查看、纠正、停用或受控删除路径；
- 记录候选形成、正式写入、检索命中、实际注入和纠正结果，以便评测记忆是否准确、有用且未越权；
- 对高风险、冲突和无法分类内容保留 `unknown / other / needs_review` 与人工出口。

除非近期业务必须，不建设全量历史自动向量化、自治多 Agent 共享记忆、跨用户原始数据学习、通用知识图谱或自动自我修改记忆 Policy。具体停止线仍由产品风险、规模、合规和近期验证目标决定。

## 推荐输出

至少形成一张记忆权威矩阵：

```markdown
| 信息类别 | 来源与性质 | 作用域 | 候选与校验责任 | 权威存储 / 引用 | 检索条件 | 修正、失效与删除 |
| --- | --- | --- | --- | --- | --- | --- |
```
